# Dossier de réalisation professionnelle - E6

## 1. Identification

| Élément | Description |
| --- | --- |
| Projet | Application de gestion d'établissement scolaire |
| Formation | BTS Services Informatiques aux Organisations |
| Option | SLAM |
| Réalisations | R1 : application WPF ; R2 : application web |
| État | Documentation et socle technique préparés ; développement des réalisations à poursuivre par le candidat |

## 2. Contexte et besoin

L'établissement doit centraliser les informations utiles à la scolarité : élèves, professeurs, classes, matières, notes, absences, documents et emplois du temps.

La solution doit fournir des interfaces adaptées aux profils utilisateurs tout en conservant une source de données et des règles de sécurité communes.

## 3. Réalisations professionnelles

### R1 — application lourde

Application desktop WPF destinée principalement au personnel administratif et aux professeurs.

Périmètre prioritaire :
- authentification ;
- gestion des élèves, professeurs, classes et matières ;
- affectations d'enseignement ;
- création d'évaluations et saisie des notes ;
- gestion des absences et retards ;
- statistiques ;
- consultation du journal des actions selon les droits.

Cette réalisation couvre principalement les compétences de conception/développement et de gestion des données.

### R2 — évolution web

Application web responsive destinée principalement aux élèves et parents, avec accès également prévu pour les professeurs.

Périmètre :
- authentification et profil ;
- tableau de bord ;
- consultation des notes ;
- consultation des absences et retards ;
- documents ;
- emploi du temps ;
- messagerie instantanée via SignalR.

R2 constitue une évolution de l'écosystème mis en place pour R1 : elle réutilise la même API, la même authentification et la même base de données.

## 4. Architecture technique

Le backend est organisé en couches :

- **Domain** : entités et règles métier ;
- **Application** : cas d'utilisation, DTO, validations et interfaces ;
- **Infrastructure** : PostgreSQL, EF Core, Identity, stockage de fichiers et journalisation ;
- **API** : contrôleurs REST, authentification, autorisation, middleware et SignalR.

Les clients WPF et web ne connaissent pas la base de données.

## 5. Utilisateurs et droits

Les rôles fonctionnels sont :
- Élève ;
- Professeur ;
- Parent ;
- Administration ;
- Administrateur.

L'autorisation combine le rôle, les permissions et le périmètre métier. Par exemple, un professeur peut gérer les notes d'une classe uniquement lorsqu'il possède l'affectation d'enseignement correspondante.

## 6. Exigences de qualité

- authentification centralisée ;
- contrôle des autorisations côté serveur ;
- validation des données ;
- HTTPS ;
- secrets hors du dépôt ;
- journalisation des actions sensibles ;
- sauvegardes PostgreSQL et test de restauration ;
- tests unitaires et d'intégration ;
- versionnement Git ;
- CI/CD GitHub Actions ;
- séparation DEV / TEST / PROD.
